Provider authentication boundary

GitHub: user PAT or GitHub App installation/user access token · Bearer
GitLab: personal, project or group token · PRIVATE-TOKEN or Bearer; OAuth · Bearer
Bitbucket Cloud: personal API token · Basic with Atlassian email; resource/OAuth token · Bearer

Provider identity → issued credential → provider permission checks → accessible evidence. Plumbline sign-in is separate. Token scopes, resource access, expiry and organisation policies limit coverage. These are vendor models, not implemented Plumbline connections. Bitbucket app passwords are deprecated.

Constraints on the evidence

Endpoint permissions and plan features · pagination and shared quotas · report expiry · provider-specific review semantics · scoped IDs · partial or inaccessible results · sensitive payloads · production and incident context · separate access to stored reports

GitHub branch-protection reads require Administration: read. Bitbucket branch-restriction reads require an admin scope; pipeline artefacts expire after 14 days. Plumbline Viewer access does not mirror provider repository membership. The accompanying document records sources, detailed answers and unresolved organisation-specific decisions.
