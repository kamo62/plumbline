# Plumbline frontend foundation

Install with `bun install`. Use `bun run dev` with the API on 127.0.0.1:8000, or run `bun run lint`, `bun run typecheck`, `bun run test`, `bun run build`, `bun run build-storybook` and `bun run test:browser`. Browser tests intercept synthetic API responses and never call the backend. Playwright needs its Chromium browser installed.

Regenerate API types with `bun run generate:api` using a Python environment with the application dependencies available. The generator imports the application in a temporary working directory with synthetic settings and invokes `app.openapi()` only; it does not invoke startup or migrations. The current list-runs response is unspecified in OpenAPI, so `src/api.ts` validates its shape and preserves unknown completeness. Regenerate when the backend contract changes; `tests/api/test_openapi_drift.py` checks the saved schema against the application.

Vite writes deployable assets to `frontend/dist` under `/ui/`. The host must mount these assets and provide a same-origin fallback to the entry point for `/ui/` router URLs, with `/auth`, `/v1` and `/healthz` routed to the API. The guard must permit the entry point and exact public build assets without exposing protected API routes. The development proxy is not a production server. No Python UI mount is changed here.

The production entry point uses external JavaScript and system fonts. A strict deployed CSP still needs integration testing: Mantine generates runtime style elements and the custom theme sets CSS properties at runtime. The host can supply a fresh per-response nonce in a `meta name="csp-nonce"` element and the matching CSP `style-src-elem` nonce for Mantine-generated style elements. Mantine and theme handling also use style attributes/CSSOM, so a nonce alone is insufficient: evaluate `style-src-attr` compatibility (potentially `unsafe-inline` for styles only) or replace those runtime styles before enforcing a stricter style policy. Keep scripts external with a restrictive `script-src`; do not add `unsafe-inline` for scripts. This integration and policy need browser verification against the deployed response. Storybook is a development artifact and has separate CSP requirements.

Theme imports use the exact JSON shape in `themes/example.json`. Colours must be six-digit hex values; text, accent, borders and focus colours are checked against the surfaces on which they appear. Themes are stored in browser local storage on this device, not in a user account. Sessions use same-origin cookies; issued token secrets appear only until dismissed or the screen is left. Connection request bodies are intentionally absent from OpenAPI because the router parses them manually to protect credentials. Connection responses are validated at runtime against handwritten types. Run list and status responses are also checked at the API boundary. Local storage can be unavailable in restricted browser environments.

Saved ADO and synthetic connections support diagnostics and queued runs; ADO can also use server-configured credentials. Queue status includes repository progress, attempt and recovery details. A worker must be running to process queued jobs. Database persistence is required for worker runs; report files are optional. Run responses expose the linked original snapshot ID. The API refuses deletion of active runs or runs with stored evidence. Authenticated `GET /connections/providers` exposes static provider requirements and capability metadata, without enabling additional SCM adapters or changing this UI's provider controls.
